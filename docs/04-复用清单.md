# 复用清单

新库不是从零写的。下面逐条写清：**借的是什么、落到本项目哪个文件、为什么不要剩下的部分**。
判断标准只有一条：**能不能减少「自己写错」的概率**。同功能的重复实现一律不要。

> 本文只记录**技术判断**，不记录具体仓库、人员或对方的内部文件结构 ——
> 这个仓库是公开的，Phase 1 也要交代码评审，写清"为什么这样选"就够了，
> 不需要把别人私有仓库的细节摆出来。

---

## 一、官方 LASER UAV System（公开仓库，BSD-3）

| 来源 | 落到本项目 | 拿的是什么 |
|---|---|---|
| `laser_msgs` 的 `TrajectoryPath` / `PoseWithHeading` | `ros2_ws/.../race_node.py::_publish_path` | 直接用官方消息发航点，不自己定一套 |
| `laser_uav_managers` 的话题/服务表 | `docs/02-官方栈接口.md` | 整理成一张能查的表，省得每次翻仓库 |
| 官方 tmux 仿真会话的结构与启动顺序 | `sim/tmux/race_session.yml` | 窗口划分、`sleep` 偏移、快捷命令的历史记录 |
| 同上，会话里那组 Race 航点 | `tools/make_courses.py` → `course/provisional_sample.json` | 赛道门位置的**唯一已知数据源**（但只是路径点，见 `docs/03`） |
| 官方 crazyflie 规划器参数里的机体极限 | `sim/configs/planning_manager.yaml` 注释 + 文档 | `max_accel 14 / max_vel 3`，自己猜不出来 |
| 官方 `install.sh` 的 **CI 非交互分支** | `sim/docker/bootstrap_lus.sh` | **直接驱动它**，不重写 —— 见下方"踩过的坑" |

**没拿**：NMPC/INDI 控制律、估计器插件、vio/lio 包。
这些是官方维护的，复制一份只会得到"一个会过期的分叉"。

**踩过的坑**：第一版 `bootstrap_lus.sh` 是照官方脚本手抄的"等价实现"，
结果漏掉 PX4 SITL 固件构建、Micro-XRCE-DDS-Agent、acados 求解器和一批依赖
—— 因为没有终端就想绕开交互，但**上游本来就有非交互开关**（`GITHUB_ACTIONS=true`）。
现在 `bootstrap_lus.sh` 只做三件事：clone、用 CI 分支跑官方 `install.sh`、覆盖 crazyflie 后重编译。

## 二、团队里另一套无人机栈（私有仓库，**只读参考**）

那套栈是"室内巡检"的：机上有 LiDAR + VIO，用 MAVROS 走 offboard，规划用 EGO-Planner。
它解决的是另一个问题，所以**只借方法，不借代码**。

| 借到的做法 | 落到本项目 | 具体是什么 |
|---|---|---|
| 起飞前把无聊的事一次查完、失败就非零退出 | `tools/preflight.sh` | `[ok]/[warn]/[fail]` 三段式输出 + 汇总后统一退出码 |
| **指令通道只能有一个发布者** | `docs/01-架构.md` + `race_node.py` 注释 | 那套栈里有专门的"setpoint 所有者"节点；LUS 里天然由 `planning_manager` 承担，所以只把约束写进文档，不搬代码 |
| 安全判定返回**带 reason code 的 verdict**，而不是散落的 bool | `racing_core/safety.py` | `Verdict(level, reasons, detail)` 一个对象说清"能不能飞、为什么不能" |
| 先验证再 arm 的顺序 | `tools/preflight.sh` | 自检通过才允许 `start` |
| 看板该显示什么 | `ground_station/` | **实现换了**（见下），只借信息结构 |
| 把踩过的坑按"现象 → 根因 → 修法"记下来 | `docs/05-踩坑与教训.md` | 这个格式比"记录一下"有用得多 |

**没拿**：整包 MAVROS、EGO-Planner、FAST-LIO、Livox 驱动、那套看板的具体实现。

**为什么**：

1. **技术栈不匹配**。那套是约 3 kg、带 LiDAR 的室内巡检机；本届是 30 g Crazyflie、
   只有一颗前视相机、走 PX4 + uXRCE-DDS。输入、坐标、控制接口全不同。
2. **搬过来等于背上两套依赖**。而"背了两套依赖"正是上一届方案失败的原因。
3. **看板重写反而更省**。那套是 Next.js 导出静态包，要 Node 构建链；
   竞赛容器、Windows 调试机、手机热点三种环境都得能开，所以换成 stdlib 单文件。

**唯一想搬但没搬的**：那套里的 3D 点云看图器。竞赛赛道以平面为主，俯视 SVG 够用，
不值得为它引一套 WebSocket + 前端构建。将来要看 3D 轨迹偏差时，那里是现成的起点。

## 三、团队里另一套平台 / 能力层（私有仓库，**只读参考**）

那套是"仓库巡检平台"：MQTT/mTLS 上报、多机调度、地图包同步、任务账本。
本届是**单机、离线、比时间**，那一层用不上，但**无人机侧的契约设计**值得学。

| 借到的做法 | 落到本项目 | 具体是什么 |
|---|---|---|
| 契约风格：状态用扁平 msg、命令用"动作字符串 + reason"、载荷用 JSON 保持向前兼容 | `ros2_ws/src/icuas27_interfaces/` | `RaceStatus.msg`、`RaceControl.srv` 的形状照这个思路设计 |
| **陈旧预算要按平台显式选择** | `racing_core/safety.py::SafetyLimits` | SITL 的心跳到墙上时钟会被仿真倍速拉长，用真机预算会疯狂误报 → `sim`/`real` 两套值，**绝不自动切换** |
| 停机语义要区分"人为急停"与"环境失效" | `racing_core/safety.py` 的 `Level` / `safe_stop` | 两者恢复条件不同，不能共用一个 bool |
| **只读观测页**：状态读取不写业务、不发命令 | `ground_station/server.py` | 看板只读，操作走 `ros2 service call` |
| 用假设备把整条链路跑通，不依赖真实硬件 | `ground_station/mock.py` + `--mock` | 没有仿真器也能验证判定逻辑 |
| 纯逻辑 + 打桩的分层测试法 | `tests/` 的组织方式 | `racing_core` 零 ROS 依赖，因此能在任何机器上单测 |

**没拿**：那套平台的业务层（MQTT broker、证书、地图包、任务账本）、ROS 1 工作区，
以及随仓库附带的平台二进制。

**为什么**：那些是"平台"的组成部分 —— 上报、同步、多机调度、鉴权。
本届不需要，而且会带来 MQTT broker、证书、SQLite 账本这些运行时依赖。
**只借"无人机侧契约怎么设计"**，不借平台。
