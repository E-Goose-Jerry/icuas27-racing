# 架构

## 一句话

官方 LUS 负责「飞」，本项目负责「飞哪扇门、算不算过、用了多久」。

```

                      │        │  └─ racing_core.mission_fsm             │
                      │        │        └─ safety.check                 │
                      │        └──► TrajectoryPath ─────────┐           │
                      │        └──► /icuas27/race_status     │           │

                      └──────────────────────────────────────┼───────────┘
                                                              ▼

   │           ▲                                     │                 │
```

## 三层各自的边界

### 1. `racing_core/` —— 纯逻辑，无 ROS

这是唯一值得写单元测试的地方，也是唯一能在 Windows 和没有 ROS 的机器上跑的部分。

| 模块 | 职责 | 明确不做 |
|---|---|---|
| `geometry.py` | 门坐标系、线段穿门判定、最近点 | 不做坐标变换树（TF 是 ROS 的事） |
| `course.py` | 门序列、圈数、JSON 加载、几何合法性校验 | 不做可视化 |
| `timing.py` | 计时、罚时账本、`T_adj` | 不读系统时钟（由调用方传入 `now`） |
| `mission_fsm.py` | 状态机、下一个目标门、漏门重试策略 | 不发话题、不调服务 |
| `safety.py` | 陈旧预算、越界/高度判定 | 不主动停机（只给 Verdict） |
| `protocol.py` | 版本化 JSON 契约、原子写 | 不渲染 |

**为什么坚持零依赖、零 ROS**：竞赛现场最贵的错误是「逻辑本身写错了但没人发现」。
把判定逻辑做成可单测的纯函数，是唯一能在不出门的情况下验证它的方法。

### 2. `ros2_ws/src/` —— 胶水层

`race_mission` 节点很薄，只做四件事：订阅位姿、喂状态机、把 `Action` 变成话题/服务调用、
把状态写成 JSON。**所有 if/else 判断都在 `racing_core` 里**，节点里没有。

`gate_detector` 同样：投影数学在 `detectors/common.py`（可单测），
OpenCV 相关在 `detectors/color_gate.py`（靠参数调）。

### 3. `ground_station/` —— 只读观测

用 `http.server` + SSE，不用 FastAPI，理由是它必须能跑在竞赛容器、Windows 调试机、
手机热点三种环境下，而多一个依赖就多一处装不上的可能。

**看板只读是刻意的**：浏览器标签页永远不应该成为「按下去会让无人机起飞」的东西。
操作走 `ros2 service call`，页面上把命令原样印出来供复制。

## 数据流上的三个约定

1. **状态文件的 `seq` 单调递增**。看板和 SSE 靠它判断「有没有新内容」，
   不靠时间戳（仿真时间可能暂停或大步跳跃）。
2. **计时用 ROS 时钟**（`get_clock()`），所以 `use_sim_time` 生效时，
   仿真里的 1 秒就是比赛成绩里的 1 秒，不是墙上时钟。
3. **罚时账本与净用时分开放**。`elapsed` 永远是真飞了多久，`adjusted` 才是排名依据；
   页面同时显示两个，避免「改了罚时把成绩也改了」的误读。

## 状态机

```
IDLE ──start──► TAKEOFF ──高度到位──► RACE ──全部过门──► LANDING ──落地──► DONE
  │                │                     │                  │
  └────────────────┴─────────────────────┴──────────────────┴──► SAFE_STOP（急停，原地保持）
                                          └────────────────────► ABORTED（中止，取消规划+降落）
```

细节：

- **开表时机**：起飞动作发出后，等到实际高度超过起飞高度的 80% 才开表。
  否则「电机的启动延迟」和「飞控起飞爬升时间」会算进成绩。
- **过门判定**：用相邻两帧位姿的线段与门平面求交，交点若在门框内且方向朝前 = 过门。
  这样判定与采样率无关，不会出现「飞过去了但某一帧没抓到」。
- **漏门策略**：先重发同一扇门最多 `retry_limit` 次（默认 2），仍不成就记 5 秒罚时、
  置 `incomplete=True`（该次不计排名，与规则书 §10 一致）、继续飞下一扇。
- **落地判定**：`LAND` 发出后等高度 < 0.15 m 才算 DONE。
